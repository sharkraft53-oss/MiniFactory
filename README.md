# Mini Factory

Тестовое задание на позицию Unity Developer.

Mini Factory — небольшой мобильный idle-проект, в котором производственные машины автоматически создают игровую валюту. Игрок может открывать новые машины, улучшать их и временно увеличивать производство всей фабрики с помощью Boost.

## Версия Unity

Unity 6000.3.22f1

Целевая платформа:

- Android

## Основные возможности

В проекте реализовано:

- 3 производственные машины;
- состояния Locked / Unlocked;
- уровни машин;
- автоматическое производство валюты;
- открытие машин за игровую валюту;
- улучшение машин;
- изменение стоимости улучшений в зависимости от уровня;
- отображение баланса и общей производительности;
- временный Boost производства;
- сохранение прогресса между запусками;
- offline production;
- ограничение максимального offline-времени;
- учет активного Boost во время offline progress;
- Unity IAP v5;
- consumable-продукт `coins_pack_small`;
- тестирование покупок через Fake Store;
- система аналитических событий;
- Console Analytics Provider;
- Edit Mode unit-тесты.

## Архитектура

Для проекта выбрана простая сервисная архитектура без дополнительного DI framework.

Основные классы:

- `GameController` — связывает основные игровые системы;
- `EconomyService` — отвечает за баланс и операции с валютой;
- `MachineModel` — хранит состояние машины и рассчитывает производство и стоимость улучшения;
- `BoostService` — отвечает за временное увеличение производства;
- `SaveService` — сохранение и загрузка прогресса;
- `AnalyticsService` — отправка аналитических событий;
- `IAnalyticsProvider` — интерфейс аналитического провайдера;
- `ConsoleAnalyticsProvider` — текущая реализация аналитики через Console;
- `IIAPService` — интерфейс для работы с покупками;
- `UnityIAPService` — реализация Unity IAP v5;
- `GameConfig` — локальная конфигурация игровых параметров.

Я старался не усложнять архитектуру сильнее, чем требуется для размера тестового проекта.

## Конфигурация

Основные игровые параметры вынесены в `GameConfig`.

Через конфигурацию задаются:

- параметры машин;
- стартовое производство;
- стоимость открытия;
- стоимость улучшения;
- множитель стоимости улучшения;
- длительность Boost;
- множитель Boost;
- возможность включения/отключения Boost;
- максимальное время offline production;
- количество валюты за IAP-покупку.

Gameplay-код не хранит эти значения напрямую.

Такой подход позволяет в дальнейшем заменить или дополнить локальную конфигурацию Remote Config без необходимости переписывать основную игровую логику.

## Offline Progress

Для определения реально прошедшего времени используется UTC-время.

При выходе из приложения сохраняется время последнего сохранения.

При следующем запуске:

1. определяется количество прошедших секунд;
2. время ограничивается значением `maxOfflineSeconds`;
3. рассчитывается базовая производительность открытых машин;
4. отдельно учитывается время, в течение которого был активен Boost;
5. рассчитанная валюта начисляется игроку.

Boost также использует реальное UTC-время, поэтому его таймер продолжает идти, даже если приложение закрыто.

## Сохранение прогресса

Прогресс сохраняется в JSON-файл через:

`Application.persistentDataPath`

Сохраняются:

- баланс игрока;
- уровень каждой машины;
- состояние Locked / Unlocked;
- время последнего сохранения;
- время окончания Boost.

Сохранение выполняется при важных игровых действиях и при сворачивании/закрытии приложения.

## Unity IAP

Используется:

`Unity In-App Purchasing 5.4.3`

Реализован продукт:

`coins_pack_small`

Тип:

`Consumable`

После успешной покупки игрок получает количество игровой валюты, указанное в `GameConfig`.

Для проверки используется Unity Fake Store.

Gameplay-код не работает напрямую с Unity IAP API. Работа с IAP выполняется через интерфейс `IIAPService` и реализацию `UnityIAPService`.

Обрабатываются:

- подключение к Store;
- получение продукта;
- успешная покупка;
- неуспешная покупка;
- ошибка инициализации IAP;
- недоступность IAP.

## Analytics

Gameplay не зависит от конкретного Analytics SDK.

Реализованы:

`AnalyticsService`

`IAnalyticsProvider`

`ConsoleAnalyticsProvider`

Текущие события:

- `game_started`;
- `machine_unlocked`;
- `machine_upgraded`;
- `boost_started`;
- `boost_finished`;
- `offline_income_applied`;
- `purchase_succeeded`;
- `purchase_failed`.

События содержат дополнительные параметры, например ID машины, уровень, стоимость, offline-время, полученный доход и ID продукта.

Архитектура позволяет в дальнейшем добавить Firebase Analytics или AppMetrica как дополнительный provider.

## Unit Tests

Добавлены Edit Mode unit-тесты для основной игровой логики.

Проверяются:

- успешное списание валюты;
- невозможность покупки при недостаточном балансе;
- открытие машины;
- повышение уровня машины;
- изменение производства после улучшения;
- изменение стоимости следующего улучшения.

Результат последнего запуска:

`4 Passed / 0 Failed`

## Запуск проекта

1. Установить Unity 6000.3.22f1.
2. При установке добавить Android Build Support.
3. Установить Android SDK & NDK Tools.
4. Установить OpenJDK.
5. Клонировать репозиторий.
6. Добавить проект в Unity Hub.
7. Открыть сцену `Main`.
8. Запустить Play Mode.

## Android Build

В Unity открыть:

`File -> Build Profiles -> Android`

Выбрать Android и выполнить Build.

Android Build Support, SDK, NDK и OpenJDK должны быть установлены через Unity Hub.

## Известные ограничения

На данный момент:

- используется простой UI, так как художественная составляющая не является основной частью тестового задания;
- Firebase Remote Config не подключен;
- используется только Console Analytics Provider;
- IAP проверяется через Unity Fake Store, без реального продукта Google Play;
- дополнительный Android profiling не выполнялся.
