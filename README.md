# Mini Factory

Тестовое задание на позицию Unity Developer.

Небольшой мобильный проект для Android, в котором игрок управляет фабрикой из нескольких производственных машин, улучшает их, открывает новые машины, использует временный Boost и получает offline-прогресс.

Проект выполнен на:

- Unity 6000.3.22f1
- Android
- C#

---

## Основные возможности

В проекте реализовано:

- 3 производственные машины;
- первая машина доступна сразу;
- остальные машины открываются за игровую валюту;
- автоматическое производство валюты;
- отображение текущего баланса;
- отображение общей производительности;
- состояния Locked / Unlocked;
- уровни машин;
- стоимость открытия;
- стоимость следующего улучшения;
- улучшение машин;
- временный Boost производства;
- сохранение прогресса;
- offline production;
- ограничение максимального offline-времени;
- корректный учёт времени Boost при закрытом приложении;
- Unity IAP;
- Fake Store;
- система Analytics;
- unit-тесты.

## Экономика

Каждая открытая машина автоматически производит игровую валюту.

Производительность машины зависит от:

- базовой производительности;
- текущего уровня машины.

Стоимость следующего улучшения рассчитывается на основе:

- базовой стоимости улучшения;
- множителя стоимости;
- текущего уровня машины.

Формулы и значения экономики находятся в конфигурации и не хранятся непосредственно в gameplay-коде.

## Машины

Каждая машина содержит:

- уникальный ID;
- отображаемое название;
- состояние Locked / Unlocked;
- текущий уровень;
- базовую производительность;
- стоимость открытия;
- базовую стоимость улучшения;
- множитель стоимости улучшений.

В проекте используется 3 машины.

Первая машина доступна сразу после начала игры.

Вторая и третья открываются за игровую валюту.

---

## Boost

Boost временно увеличивает производство всей фабрики.

Через конфигурацию можно изменить:

- длительность Boost;
- множитель производства;
- возможность включить или отключить Boost.

Активный Boost хранится не как оставшееся количество секунд, а через время его окончания.

Благодаря этому Boost корректно учитывает реально прошедшее время даже после сворачивания или закрытия приложения.

---

## Offline Progress

При закрытии приложения сохраняется время последней игровой сессии.

При следующем запуске рассчитывается время, которое игрок провёл offline.

После этого игроку начисляется валюта, которую открытые машины произвели бы за это время.

Offline production имеет максимальную продолжительность, задаваемую через конфигурацию.

Если во время offline-периода был активен Boost, повышенная производительность учитывается только для той части времени, когда Boost действительно был активен.

## Сохранение

Сохранение реализовано через JSON.

Файл сохраняется в:

`Application.persistentDataPath`

Сохраняются:

- баланс игрока;
- уровень каждой машины;
- состояние Locked / Unlocked;
- время последней игровой сессии;
- время окончания Boost.

Сохранение выполняется при изменениях прогресса, а также при сворачивании или закрытии приложения.

## Конфигурация

Основные игровые параметры вынесены из gameplay-кода.

Используется `GameConfig` на основе ScriptableObject.

Через конфигурацию задаются:

### Машины

- ID;
- название;
- доступность в начале игры;
- стартовый уровень;
- базовая производительность;
- стоимость открытия;
- стоимость улучшения;
- множитель стоимости улучшений.

### Boost

- Enabled;
- Duration;
- Multiplier.

### Offline

- максимальное время offline production.

### IAP

- количество валюты, выдаваемое за покупку.

Архитектура сделана так, чтобы в будущем локальную конфигурацию можно было заменить или дополнить Remote Config без изменения основной игровой логики.

## Unity IAP

В проект подключён Unity In-App Purchasing v5.

Реализован consumable-продукт:

`coins_pack_small`

После успешной покупки игрок получает игровую валюту.

Для проверки используется Unity Fake Store.

Реальный продукт Google Play не создавался, так как для выполнения обязательной части задания достаточно Fake Store.

Обрабатываются:

- подключение к Store;
- загрузка продукта;
- успешная покупка;
- неуспешная покупка;
- deferred purchase;
- подтверждение покупки;
- ошибка инициализации;
- ситуация, когда IAP недоступен.

Игровая логика не зависит напрямую от Unity IAP API.

Для работы с покупками используется отдельный IAP Service.

## Analytics

Реализована отдельная система Analytics.

Используется интерфейс Analytics Provider, поэтому к проекту можно подключить одновременно несколько разных Analytics SDK.

В обязательной реализации используется Console Analytics Provider.

Поддерживаются события:

- `game_started`;
- `machine_unlocked`;
- `machine_upgraded`;
- `boost_started`;
- `boost_finished`;
- `offline_income_applied`;
- `purchase_succeeded`;
- `purchase_failed`.

События содержат дополнительные параметры там, где это необходимо.

Например:

- ID машины;
- уровень;
- стоимость;
- баланс;
- размер offline income;
- ID продукта;
- причина ошибки покупки.

Gameplay-код не зависит напрямую от конкретного Analytics SDK.

## Архитектура

Для проекта использована простая service-based архитектура без дополнительного DI framework.

Для масштаба тестового проекта отдельный DI framework был признан избыточным.

Основные компоненты:

### GameController

Координирует работу игровых систем.

Отвечает за:

- обновление производства;
- открытие машин;
- улучшение машин;
- Boost;
- offline progress;
- сохранение;
- Analytics;
- IAP.

### MachineModel

Содержит игровое состояние отдельной машины.

Не является MonoBehaviour.

Отвечает за:

- уровень;
- состояние разблокировки;
- производительность;
- расчёт стоимости улучшения.

### EconomyService

Отвечает за:

- баланс;
- начисление валюты;
- списание валюты.

### BoostService

Отвечает за:

- запуск Boost;
- его длительность;
- множитель;
- оставшееся время;
- восстановление состояния после перезапуска.

### SaveService

Отвечает за:

- сохранение;
- загрузку;
- сериализацию JSON.

### AnalyticsService

Не зависит от конкретного Analytics SDK.

Поддерживает несколько Analytics Providers.

### UnityIAPService

Инкапсулирует работу с Unity IAP.

Gameplay-код работает через интерфейс IAP Service и не зависит напрямую от Unity IAP API.
