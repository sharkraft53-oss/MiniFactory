# Использование AI

При выполнении тестового задания я использовал AI как помощника при разработке.

Основным инструментом был ChatGPT.

Я использовал AI не только для генерации кода, но и для обсуждения архитектуры, проверки решений и разбора ошибок.

## Для каких задач использовался AI

AI помогал мне с:

- планированием структуры Unity-проекта;
- выбором простой архитектуры для тестового задания;
- логикой машин и экономики;
- реализацией Boost;
- сохранением прогресса;
- расчетом offline progress;
- архитектурой Analytics;
- интеграцией Unity IAP v5;
- написанием unit-тестов;
- разбором ошибок Unity;
- подготовкой README и AI_USAGE.

## Примеры ключевых промптов

Примеры запросов, которые использовались во время разработки:

> Помоги сделать простую архитектуру для тестового Unity-проекта Mini Factory без лишнего overengineering.

> Сделай систему машин с уровнями, производительностью и стоимостью улучшения.

> Помоги реализовать offline progress с ограничением максимального offline-времени.

> Сделай Boost, который работает по реальному времени и учитывается после повторного запуска приложения.

> Сделай систему Analytics так, чтобы gameplay-код не зависел от конкретного SDK и можно было подключить несколько providers.

> Помоги подключить Unity IAP v5 через отдельный сервис, чтобы gameplay не зависел напрямую от Unity IAP API.

> Сделай Edit Mode unit-тесты для экономики и логики машин.

## Что было реализовано с помощью AI

AI помогал при написании и доработке следующих частей:

- `GameController`;
- `EconomyService`;
- `MachineModel`;
- `BoostService`;
- `SaveService`;
- структуры SaveData;
- offline progress;
- `AnalyticsService`;
- `IAnalyticsProvider`;
- `ConsoleAnalyticsProvider`;
- `IIAPService`;
- `UnityIAPService`;
- unit-тестов;
- структуры документации проекта.

Полученный код не использовался полностью вслепую. После добавления кода я запускал проект и проверял работу систем в Unity.

## Какие предложения AI были изменены или отклонены

Некоторые предложения AI я изменял во время разработки.

Например:

- UI и расположение элементов были изменены вручную, потому что первоначальные размеры и позиции не подходили под мобильный экран;
- я не стал добавлять сложный DI framework, потому что для такого проекта это было бы лишним;
- Firebase Remote Config не был добавлен в обязательную часть;
- внешний Analytics SDK также не добавлялся, так как для обязательной части достаточно Console Provider;
- некоторые значения экономики и расположение UI подбирались вручную во время тестирования;
- дополнительные системы не добавлялись, если они не были необходимы для выполнения основной части задания.

## Ошибки и спорные решения AI

Во время работы я столкнулся с ситуациями, когда предложения AI требовали проверки или исправления.

Например:

- настройки Unity UI нельзя было использовать без ручной проверки — расположение элементов пришлось корректировать в Editor;
- работу Unity IAP v5 я проверял непосредственно на установленной версии пакета;
- после изменений IAP проверялся через Fake Store;
- расчет offline income проверялся по значениям в Console;
- отдельно проверялось, что Boost учитывается во время offline progress;
- после добавления unit-тестов они запускались через Unity Test Runner;
- некоторые serialized-поля приходилось вручную связывать через Inspector;
- код после изменений всегда проверялся на ошибки компиляции.
